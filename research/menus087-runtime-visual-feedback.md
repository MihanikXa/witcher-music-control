## Visual discrepancies (direct screenshot comparison)

1. **Shared header/top navigation:** Current menu consistently shows broad individually highlighted gold rectangular tabs and a large level/XP bar at top left. Reference shows a slim text-based navigation strip, minimal highlight markers, medallion at far left, compact stats/XP toward the right. This is a **major missing desired shared presentation**, not solved by a different typeface.
2. **Shared ink background engravings:** Current Glossary/Quests/Alchemy/Character images appear nearly featureless black; reference has delicate illustrations (e.g. quest compass, alchemical bottles, anatomical figure on the pictured Character alternate layout, and patterns behind Inventory slot clusters). Screenshots alone do not establish whether the background art cache is absent, image loading failed, a script callback did not run, the effective shared movie is old, or artwork is option/layout-dependent.
3. **Inventory:** Current is visually sparse with rectangular/simple slot groups around Geralt, unlike the full reference's decorative round slots/etched group markers. **The user has separately rejected the equipment orbit as a long-term composition**. Do not blindly recreate the orbit in the custom Inventory v2. This mismatch is evidence that a release advertised as the complete visual menu baseline does not resemble the intended mod reference.
4. **Text and typography:** Current uses accepted QuietFolio/Gentium/Vanilla Fonts bridge, while official mod-page samples use IM Fell. The different letterforms, case, width, line spacing and perceived elegance are partially deliberate; do not silently replace the custom EN font to match screenshots.
5. **Bestiary art:** Current shows vanilla-like realistic creature imagery; reference has etched/ink creature art. **Official mod documentation identifies Bestiary Art as an optional separate Glossary module, no longer in All-in-One since 0.8.1**. `research/menus087-baseline.md` explicitly deferred this module. This is a known omitted module rather than automatically a broken Glossary renderer.
6. **Character figure:** Official changelog explicitly identifies the anatomical engraving in the **"Vanilla Ironed" Character layout alternative** (`iiCharacterLayout`), whereas default is "Ink & Iron". Our release adds `iiCharacterLayout`; verify actual option selection and its resources before attributing absence of the figure to asset loss.
7. **Other aesthetic differences:** Font choice, differing characters/levels, layout presets, separate optional icons/bestiary modules and image crop affect strict one-to-one matching. Separate known expected divergences from actual integration faults.

## Grounded package/repo evidence

- `0ae30c3` shipped `modInkIronMenus087`, with **38 .redswf movies**, **24-entry I&I UI texture.cache**, UI menu annotation scripts and nine additive options inside the existing `modInkIronHUDBatch.xml`. Native validate reported zero resource errors and **15 targeted offline tests** passed. **None** exercised the *deployed runtime effective winner*, loaded background art, rendered new top navigation, full screenshot parity, runtime option-category resolution or controller/manual tab switching.
- Its new combined `panel_common.redswf` was designed to add/retain Outfit Wheel and upstream Ink & Iron `MenuCommon`/new `TopBarNew`. The previously accepted **RC2 mod also owns `common/panel_common.redswf`**. The release instructions required Menus v1 to win `panel_common` **ahead** of RC2. If RC2 wins in the current `mods.settings`, the original header and missing `inkart:` background handling are a strong shared explanation. But the user's screenshots do **not** establish the effective owner or whether the new `TopBarNew` actually initializes; confirm it read-only.
- The release code carries a `TopBarNew.qfMenuPadIcon` compatibility patch against RC2's `InputFeedbackButton`. A failed/shared class reference, wrong initialization branch or falling back to the old tab implementation could also produce the legacy header even when the package owns its SWF. Do not infer that the old-looking header proves bad load order.
- `inkironui_bgart.ws`, `MenuCommon`'s `inkart:` handling and the 24 art-cache keys are packaged. Why decorative art appears absent is **not yet established**. Confirm the runtime script dispatch, menu resource winner, symbols/source paths and actual cache lookup, not merely ZIP contents. Check whether the 0.8.7 art actually requires other optional modules.
- `tools/compile-menus-087.py` adds **nine option Var nodes to the existing file named `modInkIronHUDBatch.xml`**, although 0.8.7 scripts read values from `InkAndIronOptions`. Verify actual root category/group, loaded config namespace, default values and whether in-game options take effect. Passing the XML merge test is insufficient to prove runtime `GetVarValue('InkAndIronOptions',...)` returns intended values. Do not assert an options bug without checking.
- The package intentionally excludes optional Bestiary Art, IM Fell Fonts, Animated MainMenu and unchanged player HUD; these omissions must be **explicitly listed** against the user's desired mod-page presentation, rather than calling the mod-page look completely installed.
- The reference screenshots may show different menu variants, optional packs and character progress. Compare the same save/options/screens where possible.
