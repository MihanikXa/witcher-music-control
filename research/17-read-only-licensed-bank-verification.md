## Acceptance rules

**Baseline must pass first.** Its generated `Init.bnk` remains disposable even if it matches native; passing this workflow does not authorize shipping it.

| Gate | Required evidence / failure behavior |
|---|---|
| Current tool/source provenance | Generation log banner v2023.1.19/build8928; project and input manifest schema119/build8928; all 1,508 original WWU paths/hashes match the untouched copy. No leaf-inclusion experiment; copied originals match their input hashes. |
| Generation | `result.json` exit0 and exactly Init/music_prologue; log has no error/fatal/media-limit/licence diagnostics. All warnings currently stop for review, including the retained Wwise.dat warning. Code2 is not automatically accepted. No key or log message is copied into verification reports. |
| BKHD | v150, expected native bank IDs1355168291/3228744150, same native/generated language, alignment flags, nonzero matching ProjectID, bank type and padding. ProjectID0 vs39 explicitly fails. |
| Bank hash | Generated bytes24–39 must match SoundbanksInfo.xml's Hash GUID in GUID byte order. This corroborates metadata, not an independently implemented bank-hash algorithm. A different bank hash is reported separately from incompatible identity fields. |
| HIRC | Untouched regional and Init HIRC chunks must match native byte-for-byte; all added/removed/changed IDs/types/body lengths reported. Missing buses/devices/effects, or changed references in opaque bodies, fail; no guessed repair or waiver. Even unexplained record-order differences stop. |
| INIT registrations | Decode complete count/u32ID/NUL-name table, reject duplicate IDs/truncation/trailing bytes, and compare all IDs/names. Empty names are preserved: native IDs11403271/11862023 use empty names (report12's registration evidence). Missing/added/renamed entries fail. |
| STMG/global data | Entire STMG must match native, including the undecoded tail. Report lengths/SHA256 and decoded StateGroups/default/custom transition times. ENVS, PLAT and every other non-BKHD chunk must also match. Matching one StateGroup alone never clears global fidelity. |
| Native Init provenance | Reference native Init must match the installed game's loose Init SHA256. Generated Init is compared but never substituted. |
| Candidate binding | Recompute baseline acceptance and require a prior passing baseline report whose complete input hashes still match. Missing, failed or stale baseline proof blocks candidate validation. |
| Candidate State edit | Reuse existing State audit: one changed world HIRC ID1033516231/type12; exact native prefix/suffix around the inline block; one additive dB property0, group766723505, immediate sync, exactly nine policy-named E/D overrides at -200. No new HIRC IDs; combat/other zero additions omitted. Native global State source/group and transitions remain present. |
| Candidate source/media | Only world StateInfo changes semantically; all unrelated WWUs unchanged; saved clean-authoring audit passes. Candidate original-media manifest/hashes equal baseline; all converted WEMs match, DIDX/DATA and non-world HIRC remain native-exact. No source inclusion experiment or fixture workspace. |
| Candidate Init | Existing structural audit requires byte-identical baseline/candidate Init, in addition to the wrapper's global/header/metadata checks. An unexpected hash-only Init change therefore still stops for review. |
| Unknown regional changes | Only BKHD and the verified world HIRC change are permitted; new/changed chunks or unresolved headers/dependencies fail. No arbitrary exception list is available. |
| Read-only evidence | Hash all inspected bank/source/metadata/log/media inputs before and after; changes during verification fail. Outputs must be fresh, under build, outside all input directories; prior evidence is never overwritten. |

These are deliberately strict offline gates. Exact native HIRC/global payload preservation supplies dependency preservation for the existing graph; this is **not** a general decoder of every opaque bus/device/plugin reference. The only new regional semantic dependency is the decoded existing StateGroup. Codec/plugin DLL loading and native Music behavior still need the separately authorized runtime tests in report16.

`passed:true` is an offline gate result; `deployable:false` and `runtime_validated:false` remain explicit. A candidate pass permits the separate cooker proof, not installation, licence acceptance, licence publication rights or a claim of a working mod. Clean generation is only evidence of effective build coverage, not account approval verification.

## Commands ready after approval and separately prepared builds

These commands **do not create or regenerate banks**. They assume the user has confirmed effective entitlement and the untouched full-project baseline was separately generated under report16, retaining `result.json`, complete `generation.log` and `SoundbanksInfo.xml` alongside its banks. Source paths below are proposed isolated build paths; native paths are explicitly labelled machine-local evidence.

First, validate only the untouched baseline:

```powershell
python tools/white_orchard_build_gate.py baseline `
  --native 'L:\Games\Steam\steamapps\common\The Witcher 3 REDkit\r4data\soundbanks\Pc' `
  --game-init 'C:\Program Files (x86)\Steam\steamapps\common\The Witcher 3\bin\initialdata\sound\Init.bnk' `
  --baseline build/licensed-white-orchard/baseline-banks `
  --baseline-project build/licensed-white-orchard/baseline `
  --output build/licensed-white-orchard-verification/baseline.json
```

Exit1 means stop. Read `failures`, bank header/record differences, plugin registration differences and full STMG comparison. Missing/malformed evidence produces a failed JSON report. A malformed input does not become acceptance because some independent checks passed. Fresh output names are required on retries.

Only after baseline pass and the candidate is separately authored/generated with equivalent licensing/build setup:

```powershell
python tools/white_orchard_build_gate.py candidate `
  --native 'L:\Games\Steam\steamapps\common\The Witcher 3 REDkit\r4data\soundbanks\Pc' `
  --game-init 'C:\Program Files (x86)\Steam\steamapps\common\The Witcher 3\bin\initialdata\sound\Init.bnk' `
  --baseline build/licensed-white-orchard/baseline-banks `
  --baseline-project build/licensed-white-orchard/baseline `
  --baseline-report build/licensed-white-orchard-verification/baseline.json `
  --candidate build/licensed-white-orchard/candidate-banks `
  --candidate-project build/licensed-white-orchard/candidate `
  --output build/licensed-white-orchard-verification/candidate.json
```

Candidate mode rechecks the baseline and binds the accepted proof to unchanged inputs. The detailed State report is `candidate-state-detail.json`; the top-level report gives the strict decision. The underlying historical structural audit may succeed alone even when compatibility is unresolved; use this wrapper's exit status and top-level `passed`, not that structural exit code as the build gate.
